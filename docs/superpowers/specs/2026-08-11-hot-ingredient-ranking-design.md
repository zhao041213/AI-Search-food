# 热门食材图片排行榜设计

## 目标

基于所有用户和匿名访客成功生成菜谱后产生的 `search_logs`，统计热门食材，并同时提供：

- 用户端：前 10 名图片卡片排行榜，可按全部、近 7 天、近 30 天切换。
- 管理员端：横向柱状图和统计明细表，可查看次数、占比和最近搜索时间。

统计接口不返回用户编号、手机号、匿名标识等个人信息。

## 数据设计

新增 `search_log_ingredients` 明细表，每条搜索记录中的每种标准食材保存一行：

- `search_log_id`：关联 `search_logs.id`，搜索日志删除后级联删除。
- `ingredient_name`：归一化后的食材名，用于聚合。
- `original_name`：用户输入或识图得到的原始名称。
- `created_at`：沿用搜索日志时间，确保历史统计时间窗口准确。

同一条搜索中的同一种标准食材只记录一次，唯一键为 `(search_log_id, ingredient_name)`；`(ingredient_name, created_at)` 建联合索引。

## 归一化规则

- 支持逗号、中文逗号、顿号、分号和换行分隔。
- 去除首尾空白并忽略空项。
- 合并常见别名，例如 `西红柿 -> 番茄`、`马铃薯 -> 土豆`、`花椰菜 -> 西兰花`。
- 保持首次出现顺序，对标准名称去重。

成功生成菜谱后，在同一事务中先写入 `search_logs`，再写入标准食材明细。应用启动时幂等回填没有明细的历史搜索日志；单条历史 JSON 损坏时记录警告并跳过，不阻塞应用启动。

## 接口设计

公开接口：

```http
GET /api/stats/hot-ingredients?period=all&limit=10
```

`period` 支持 `all`、`7d`、`30d`，`limit` 范围为 1 到 50。非法参数返回 400。

响应数据：

```json
{
  "period": "30d",
  "totalSearches": 210,
  "totalIngredientOccurrences": 486,
  "generatedAt": "2026-08-11T16:00:00",
  "items": [
    {
      "rank": 1,
      "name": "番茄",
      "searchCount": 128,
      "share": 0.2634,
      "latestSearchAt": "2026-08-11T15:42:00"
    }
  ]
}
```

`share` 为该食材出现次数除以当前时间范围内食材明细总数。

## 前端设计

### 用户端

- 左侧“功能扩展”首个入口改为“热门食材”。
- 新增 `/stats/hot-ingredients` 页面，默认显示全部时间的前 10 名。
- 使用稳定尺寸的图片卡片，前三名突出排名，其余保持一致的信息密度。
- 点击卡片返回智能工作台，并把食材名预填到输入框，不自动调用 AI。
- 提供加载、空数据、错误和图片加载失败状态。

### 管理员端

- 管理后台增加“热门食材”页签，不挤压现有 AI 配置页面。
- 左侧横向柱状图展示前 10 名，右侧表格展示前 20 名的排名、名称、搜索次数、占比和最近搜索时间。
- 图表使用现有 ECharts 依赖，跟随当前主题变量并响应容器大小变化。

### 图片资产

常见食材使用本地静态图片映射，未知食材使用统一的本地回退图。页面不依赖第三方运行时图片链接，因此离线开发和后续 Nginx 部署都能正常展示。

## 验证范围

- 迁移脚本创建明细表、唯一键和索引。
- 归一化、别名合并、去重。
- 新搜索事务写入日志及食材明细。
- 历史日志回填幂等且坏数据不阻塞。
- 全部、7 天、30 天聚合及占比正确。
- 接口公开访问、非法参数返回 400、响应无个人信息。
- 前端构建通过，桌面端和移动端无溢出、遮挡或空白图表。
